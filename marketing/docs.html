System Documentation

KALKI is a sovereign, local-first AI desktop operating workspace. It integrates continuous conversational intelligence, an always-on-screen companion pet, native ShieldCore antivirus defense, and cognitive multi-model routing into a cohesive, machined graphite environment.

Sovereignty Principle: KALKI operates exclusively on 127.0.0.1:8765. No user telemetry, system metrics, or unprompted audio recordings are ever transmitted to third-party servers. All API credentials and conversational memories are encrypted using machine-bound DPAPI + AES-256 keys.

Quickstart Installation

KALKI can be launched as a standalone native installer (.exe / .sh / .tar.gz) or directly from source on any Python 3.10+ runtime:

bash • terminal 
# Clone the repository
git clone https://github.com/maher-kalki/KALKI.git
cd KALKI

# Create and activate Python virtual environment
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Launch KALKI Sovereign Workspace
python -m app.main_app

By default, the server initializes on http://127.0.0.1:8765 and launches the native WebView2/PyWebView application window alongside the standalone Codex Companion Pet.

REST & SSE API Reference

The loopback server exposes 83 documented endpoints. All endpoints require loopback origin verification.

POST SSE /api/chat
Primary conversational streaming route. Dispatches user input through the cognitive router, manages multi-turn history, extracts semantic memory in background threads, and streams generated markdown tokens via text/event-stream.
json • request body 
{
  "message": "Analyze the Shannon entropy of C:\\malware.bin and quarantine it.",
  "conversation_id": "conv_948201",
  "model_override": null,
  "stream": true
}
POST /api/command
Direct deterministic operating system executor. Intercepts native commands like "lock workstation", "volume 50", "launch spotify", or "mute" and invokes OS kernel API calls via ctypes.windll.user32 or Linux D-Bus.
json • request body 
{
  "action": "lock_screen"
}
GET /api/status
Returns real-time health telemetry including CPU/RAM load, active model provider, ShieldCore defender status, loopback socket latency, and pet companion state.
GET /api/media/now
Polls active media sessions via WinRT (Windows) or playerctl (Linux). Returns playback state, track title, artist, album, duration, and embedded or iTunes-resolved album cover art.
POST /api/security/scan
Executes a multi-phase endpoint security audit: Shannon entropy scanning across executable folders, Windows Defender telemetry bridge, and background cryptominer PID checking.
GET /api/memory/list
Retrieves categorized semantic memories filtered by topic chips (Preferences, Projects, Personal, Work, Music, Tech). Encrypted with DPAPI.
POST /api/config/save
Persists API credentials and preferences into the encrypted vault. Never stores plaintext keys on disk.

Security & Cryptography Model

KALKI implements a defense-in-depth security model to safeguard user privacy and API keys against malware extraction:

1. DPAPI & AES-256-GCM Envelope Encryption

On Windows, all sensitive secrets (Gemini, OpenAI, Anthropic, Groq API keys, and semantic memory vectors) are encrypted using Windows Data Protection API (CryptProtectData). Keys are derived from the user's logon security token and TPM hardware:

python • app/vault.py 
# Key Encryption Wrapper
import ctypes
from ctypes import wintypes

def encrypt_dpapi(plaintext: bytes) -> bytes:
    """Encrypts buffer with Windows DPAPI machine/user token."""
    # Machine-tied DPAPI encryption call
    blob_in = DATA_BLOB(len(plaintext), ctypes.cast(plaintext, ctypes.c_char_p))
    blob_out = DATA_BLOB()
    if CryptProtectData(ctypes.byref(blob_in), "KALKI_KEY", None, None, None, 0, ctypes.byref(blob_out)):
        return ctypes.string_at(blob_out.pbData, blob_out.cbData)
    raise RuntimeError("DPAPI encryption failed")

2. Loopback Isolation Guarantee

The HTTP server binds strictly to 127.0.0.1. Socket connections originating from external network interfaces are rejected by the kernel. Host header verification prevents DNS rebinding exploits from untrusted browser tabs.

3. Zero Third-Party Telemetry Audit

Zero analytics trackers (Google Analytics, Sentry, Mixpanel, Segment) exist in KALKI's codebase. Network traffic can be audited using Wireshark; only user-initiated LLM prompts exit loopback.

Multi-Model Cognitive Router

KALKI eliminates manual model switching by inspecting prompt intent, token budget, and complexity heuristics:

  • Fast / Conversational Queries: Routed to ultra-low-latency models (Gemini Flash, Groq Llama-3.3-70B, or local Ollama).
  • Coding & Refactoring: Routed to specialized code models (Claude 3.7 Sonnet, DeepSeek V3/R1, or GPT-4o).
  • Deep Mathematical / Logical Reasoning: Routed to thinking models with extended chain-of-thought budgets.
  • Local Fallback Mode: When offline or no internet is available, requests route automatically to local Ollama (http://localhost:11434) without user interruption.

Anger Mode & Uncensored Persona

KALKI includes a fully configurable sentiment engine. If the user uses abrasive or colloquial language, KALKI dynamically drops corporate assistant pleasantries, mirroring the user's emotional intensity without preachy moralizing or corporate disclaimers.
